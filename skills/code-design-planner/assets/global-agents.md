## 通用开发协议

功能开发、行为修复、接口或数据变更、跨模块重构使用全局 `code-design-planner` 技能。
读取该技能的 SKILL.md，并读取当前项目生效的 AGENTS.md；技能定义流程，项目指令定义项目知识。
若找不到技能，说明缺失并在当前请求范围内按下述流程继续，不假装已加载，不擅自安装依赖。

Requirement → Design → Implementation → Verification → Review → Fix → Done。
实现前先明确验收和范围，再由 Planner 形成设计；一般功能在 docs/designs/ 下维护一份活文档，
已有项目设计位置则沿用。大任务增加必要调研和独立评审。
仅无行为变化的微小修正可用简短记录，不强制创建设计目录，仍检查 diff 与必要验证。

G1：需求可行动。G2：设计可实施且在当前授权范围内。G3：必要验证通过、当前 diff 已审阅、
验收和必要修复关闭。仅在用户或项目明确要求人工批准，或下一步超出授权时等待确认。
只设计或只 review 的请求遵守其范围；完整开发请求持续推进，不在每一阶段重复请求批准。

实现偏离设计或文件范围明显扩大时先解释并更新设计。最终进入 Reviewer Mode，检查实际
分支提交、暂存、未暂存和相关未跟踪文件，以及真实测试结果。必要修复后复验、复审。
关键验证缺失时不能声称 Done；Done 不等于获准自动 merge、deploy 或发送外部消息。
项目只保存自身架构、领域、目录与验证命令，不复制一整套全局技能或流程。
